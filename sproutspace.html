Proposal Overview

The Environment is an Active Partner in Learning

SproutSpace is a Singapore-hosted digital portal that helps every educator at Busy Bees design safe, age-appropriate classroom layouts and manage learning resources with the same rigour we bring to pedagogy. Across our network of centres - serving Infant Care through K2 - it turns the physical learning space from an afterthought into a deliberate, evidence-based instrument of quality.

It serves three audiences at once: teachers who plan and run the room, Centre Directors who own safety and quality, and HQ administrators who set standards and control spend.

S$150,000 over 12 months

ECDA Innovation Sandbox. A self-contained submission with its own budget, KPIs and 12-month plan, deployable across our pilot centres.

Layout Planner QR Inventory Leadership Control Pilot Centres SG-Hosted PDPA

Shared Stack, Broadest Build

SproutSpace runs on the same React + FastAPI foundation as PedaForge Classroom & Leadership - one stack, one skill set, lower delivery risk. It is a custom build (drag-and-drop layout canvas, QR inventory, HQ dashboards) that stands on proven open-source libraries for the commodity surfaces, with the engineering effort spent on Singapore-specific ECDA/SCDF safety logic. AI runs throughout (~30-40%) on the same Azure OpenAI enclave.

The Problem

Three Gaps in How We Plan & Resource Our Spaces

Across the network, the physical learning environment is managed manually and in isolation. The result is wasted educator time, hidden cost, and avoidable safety risk.

2.1

Difficult, Manual Layout Planning

Teachers map classrooms on paper or in basic apps. It is hard to plan age-appropriate spaces, clear movement paths and flexible corners while keeping every child fully visible for safety. The outcome is clutter, poor use of space and layouts that are never safety-checked before children arrive.

2.2

Disorganised, Untracked Resources

Inventories live on isolated spreadsheets with no shared visibility between rooms or centres, and no way to log or share teacher-made resources. The result is duplicate buying, forgotten stock and worn items that are never rotated out of children's reach.

2.3

No HQ Visibility or Budget Control

HQ cannot see resource usage, lifespan or replacement needs across centres, forcing reactive, last-minute purchasing. There is no mechanism to enforce consistent brand and safety standards across all branches at once.

Local research grounding
The need is documented in Singapore's own sector evidence. The well-being and workload pressures on educators are reported by Toh (AsiaOne, 2026) and The Straits Times (2024); the link between intentional environment design and learning quality is reflected in NTUC First Campus (2023), the Singapore University of Social Sciences (SUSS, n.d.), and Leong (2023). SproutSpace operationalises these findings as a practical, day-to-day tool.
The Solution

One Portal, Three Connected Modules

SproutSpace pairs an intuitive design tool for teachers with an active resource portal and a leadership control layer for HQ - so safe, well-resourced rooms become the standard, not the exception.

1

Interactive Layout Planner

A drag-and-drop floor-plan canvas where teachers select the age group - Infant, Toddler, Playgroup, N1, N2, K1 or K2 - and arrange furniture to scale. Built-in real-time safety warnings flag visibility blockages and hazards as the room is built, and brand-guideline presets keep every centre on-standard from the first draft.

Technology

A React + FastAPI Web Platform, Singapore-Hosted

SproutSpace is built on the same React front end and FastAPI back end as the other two proposals, hosted entirely in Singapore. It is a custom build that stands on proven open-source libraries for commodity surfaces, so the engineering budget is spent on the Singapore-specific safety rules, not on reinventing plumbing.

Build the IP, Reuse the Libraries

SproutSpace shares one React + FastAPI foundation with PedaForge Classroom and Leadership - a single stack and skill set that lowers delivery risk across all four. We evaluated mature open-source applications (Snipe-IT, Shelf.nu, InvenTree for inventory; Metabase, Superset for dashboards) and chose not to base the product on them: none encodes ECE / ECDA / SCDF safety logic, and each adds copyleft-licence and second-stack friction. Instead we stand on permissive open-source libraries - a canvas engine for the layout planner, charting for the dashboards, QR scan and label generation - and spend the engineering effort on the bespoke IP: the safety-rule engine, the ECE taxonomy, the Handmade Resource Repository and the HQ standards-push. AI runs throughout (~30-40%) on the same Azure OpenAI closed tenant.

React + FastAPI Native QR AI ~30-40% Permissive OSS Libraries

Secure Singapore Infrastructure

  • Application and database hosted on secure servers physically located in Singapore (full data residency).
  • Encryption of data in transit and at rest, with role-based access control across the centre network.
  • Automated backups for resilience and recovery.
  • Strict PDPA compliance for all centre, resource and layout data.

Roadmap & Budget

A Disciplined 12-Month Delivery Plan

Four phases take SproutSpace from needs-finding with all Centre Directors to a v1.0 launch wired into live leadership dashboards. The programme commences 01 January 2027.

Implementation Roadmap

Phase & Timeline Key Activities Success Indicators
Phase 1
Months 1–3		 Needs-finding with all Centre Directors; gather classroom sizes and safety rules across the network. Requirements signed off; pilot cohort confirmed.
Phase 2
Months 4–6		 Build the drag-and-drop layout tool with real-time safety guardrails, the central database and the QR generator. Core blueprint tested; tool reliably flags safety issues during design.
Phase 3
Months 7–9		 Beta rollout to all pilot centres; migrate existing spreadsheets into the portal; train teachers and Directors. >90% active usage; >3,500 resources logged.
Phase 4
Months 10–12		 Launch v1.0; connect resource-usage data to the leadership dashboard; complete the final evaluation report. Setup & logging time reduced by >30 hours per centre per month.
